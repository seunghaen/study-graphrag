## 잘못 알고 있었던 것

### 1. 임베딩이 "그래프를 통째로 벡터로 바꾸는 것"인 줄 알았다 ← 제일 크다

4주차 메모리 계산 얘기가 나왔을 때 나는 이렇게 물었다.

> "지금 그래프는 임베딩한 거 아냐?"
> "그래프DB를 다시 벡터로 임베딩하는 거야?"

두 번이나 되물었다. 내 머릿속 그림은 **DB 전체가 벡터 덩어리로 변환되는 것**이었다.
그래프가 사라지고 숫자만 남는 줄 알았다.

아니었다. **노드에 프로퍼티 하나가 추가될 뿐이다.**

```
(Paper)──CITES──→(Paper)      ← 관계 141만 개는 아무 일도 안 당함
 title: "..."
 abstract: "The dominant..."
 embedding: [0.02, -0.45, ...]  ← 이 줄만 새로 생김
```

임베딩의 입력은 **초록 텍스트 한 덩이**고 출력은 실수 배열이다.
그래프 구조는 임베딩에 들어가지도 않는다.

왜 헷갈렸나 돌아보면, "벡터DB"라는 말 때문이었던 것 같다.
벡터DB가 따로 있는 줄 알았으니, 그래프를 그쪽으로 **옮기는** 그림이 그려졌다.
실제로는 CLAUDE.md에 이미 **"벡터도 Neo4j 안에 — 별도 벡터DB 없음"** 이라고
내가 적어놨는데도 그 문장의 뜻을 몰랐다.

> **적어놨다고 아는 게 아니다.** 8/13에 `A→X←B`로 똑같은 걸 겪었는데 또 겪었다.

그리고 이건 크기 문제로 이어진다 — 4주차에 5만 × 1024차원 × 4바이트 =
**205MB가 추가**된다. 지금 214MB니까 DB가 두 배가 된다. 인스턴스를
지금 크기만 보고 고르면 4주차에 모자란다.

### 2. 데이터가 도커 컨테이너 "안"에 있는 줄 알았다

그래서 이렇게 물었다.

> "그 도커를 AWS에 그대로 옮겨야 하는 거 아냐?"

컨테이너를 통째로 들어서 옮기는 그림이었다. 확인해보니 아니었다.

```
docker inspect neo4j-study
→ TYPE=volume  SRC=/var/lib/docker/volumes/neo4j-data/_data  DST=/data
```

**이미지에는 내 데이터가 없다.** `neo4j` 이미지는 전 세계가 받는 똑같은
프로그램이고, 내 214MB는 `neo4j-data`라는 **볼륨**에 따로 있다.
EC2에서 `docker pull` 하면 프로그램은 1분이면 생긴다.
옮겨야 하는 건 볼륨뿐이다.

다행히 8/12의 내가 **이름 있는 볼륨**(`-v neo4j-data:/data`)으로 만들어놨다.
익명 볼륨이었으면 컨테이너를 지우는 순간 같이 날아갈 뻔했다.

### 3. "어차피 재적재해야 하는 거 아냐?"

당연히 처음부터 다시 긁는 건 줄 알았다. 그런데 재적재에는 함정이 있다.

**OpenAlex는 살아있다.** 8/12에 긁은 것과 오늘 긁는 게 다르다.
논문이 추가됐고 인용이 늘었다. 재적재하면 노드 수도 삼각형 개수도 달라진다.

그런데 CLAUDE.md에 박혀 있는 숫자들 — 삼각형 50.9만 개, 허브 임계값 7,
논문당 10.2개 — 은 **8/12 그래프를 실측한 값**이다.
재적재하면 그 근거가 존재하지 않는 그래프를 가리키게 된다.

> 8/13에 "표본이 거짓말했다"로 배운 게 재현성이었는데, 여기가 같은 함정이었다.

### 4. SAA에서 배운 이관 도구가 여기 쓰일 줄 알았다

dump니 볼륨 복사니 하는 얘기가 나왔을 때 위화감이 들었다.
SAA에서 배운 건 DMS, Snowball, DataSync, MGN 같은 것들이었는데 하나도 안 나왔다.

이유는 **규모**였다.

| 도구 | 대상 | 내 상황 |
|---|---|---|
| Snowball | 수십 TB~PB (장비를 택배로 받음) | 214MB |
| DMS | 이기종 DB 무중단 변환 | **Neo4j 미지원** |
| DataSync | 대용량 파일시스템 동기화 | 파일 한 개 |

214MB는 `aws s3 cp` 한 줄이면 끝난다.

> **자격증은 큰 문제를 가르친다. 내 문제는 작다.**
> 배운 도구를 찾는 게 아니라 문제 크기에 맞는 도구를 고르는 거였다.

### 5. CLAUDE.md에 "버전 25"라고 적어놨는데 실제는 2026.06.0

```
docker exec neo4j-study neo4j --version
→ 2026.06.0
```

Neo4j가 `5.x` → `2025.x` → `2026.x`(연.월)로 체계를 바꿨다.
0주차의 내가 `2025.x`를 보고 "25"로 줄여 적은 것 같다.
벡터 인덱스는 어차피 되지만, **이관할 때 양쪽을 대조할 숫자**라 그냥 두면 안 됐다.

## Claude가 깔아놓은 전제 두 개가 틀렸다

오늘 제일 값진 부분. **내가 물어서 뒤집힌 것들이다.**

### 1. "리전은 Bedrock과 묶여 있어서 틀리면 전부 다시"

리전 얘기를 꺼내면서 Claude가 이렇게 말했다. 그런데 확인해보니 과장이었다.

**EC2 리전과 Bedrock 리전은 따로 고를 수 있다.** Bedrock은 그냥 HTTPS API라
서울 EC2에서 us-east-1 Bedrock을 부르는 게 정상 동작한다.
왕복 200ms쯤 붙는데 LLM 응답이 수 초라 묻힌다.

즉 **6주차에 Bedrock 리전을 따로 정해도 늦지 않는다.**
"틀리면 전부 다시"라는 압박이 애초에 없었다.

### 2. "ingest.py는 맥북에서 돌린다" ← 아무 근거 없는 전제였다

이게 더 크다. Claude가 이 전제를 깔고
"그럼 ingest.py가 EC2 Neo4j에 어떻게 붙을까"를 물었고,
거기서 SSH 터널 vs 직접 접속(A/B) 비교가 나왔다.

나는 A/B가 계속 이해가 안 됐다. 몇 번을 다시 설명받아도 안 잡혔다.
그러다 이렇게 물었다.

> "임베딩도 EC2에서 돌리면 되잖아. 왜 로컬에서 만들어서 EC2랑 붙여서
> 코드를 실행하는 거야? 이게 정석이야?"

**정석이 아니었다.**

| 상황 | 정석 |
|---|---|
| 짧은 개발·디버깅 | 로컬에서 원격 DB 붙기 — 흔함 |
| **긴 배치 (적재, 임베딩 5만 개)** | **서버에서 실행** |

긴 배치를 노트북에서 돌리면 뚜껑 닫으면 죽고 와이파이 끊기면 죽는다.
EC2에서 돌리면 맥북을 꺼도 계속 돈다.

그리고 EC2 안에서 다 돌면 **7687을 인터넷에 열 이유가 아예 없다.**
A/B 고민 자체가 잘못된 전제에서 나온 것이었다.

> **내가 이해 못 한 게 내 무지 때문이 아니라 전제가 이상해서였다.**
> "이게 정석이야?"라고 물은 게 그걸 깼다.

### 3. SSH를 기본으로 제시한 것도 최선이 아니었다

"왜 SSH를 쓰는 거야?"라고 물었더니 **SSM Session Manager**가 나왔다.
SAA에서 본 그거다.

| | SSH | SSM |
|---|---|---|
| 인바운드 포트 | 22번 열어야 함 | **0개** |
| 키 파일 | `.pem` 관리 | 없음 |
| 인증 | 키 | **IAM** |
| 접속 기록 | 직접 설정 | CloudTrail 자동 |

Claude가 SSH를 먼저 꺼낸 건 "어디서나 되는 방식"이라서였는데,
**AWS 실습이 목표인 나한테는 SSM이 더 맞았다.** IAM 역할을 직접 만들어봐야 하니까.

> 세 번 다 **내가 물어서** 뒤집혔다. 그냥 따라갔으면 셋 다 그대로 갔을 것이다.

## 막힌 지점 — SSH를 안 써봤다

A/B가 안 잡힌 이유 중 하나는 단순했다. **SSH를 한 번도 안 써봤다.**
백엔드 3년 하면서 서버에 직접 들어갈 일이 없었다.

`ssh ubuntu@1.2.3.4`를 치면 프롬프트가 바뀌고, 그 뒤로 치는 명령은
전부 원격 서버에서 실행된다는 것. 이 기본을 몰라서 `-L` 옵션 설명이
공중에 떠 있었다.

**모르는 걸 모른다고 말한 게 제일 빨랐다.** 세 번쯤 "이해 안 됨"이라고
말하고 나서야 SSH부터 설명이 시작됐다.

## 새로 알게 된 사실

### Neo4j는 메모리를 두 덩이로 쓴다

자바라서 JVM 힙이 있는 건 알았는데, **하나가 더 있었다.**

| | 담는 것 | 모자라면 |
|---|---|---|
| **JVM 힙** | 쿼리 중간 결과 | **OOM → 프로세스 죽음** |
| **페이지 캐시** | 그래프 파일 자체 | 디스크 읽어서 **느려짐** |

페이지 캐시는 **힙 바깥**(off-heap)이다. `-Xmx`를 키워도 안 늘어난다.

Spring 앱은 데이터를 남(DB)한테 맡기니까 힙만 보면 되는데,
**Neo4j는 자기가 DB라서 데이터 파일을 자기가 들고 있어야 한다.** 그래서 하나가 더 필요하다.

결과가 다른 게 핵심이다 — 힙이 모자라면 죽고, 페이지 캐시가 모자라면 느리다.

t3.small(2GB) 배분: OS 450MB + 힙 512MB + 페이지캐시 1GB.
4주차 데이터 420MB는 페이지 캐시에 들어간다. 5주차 확장 쿼리에서
힙 512MB가 버틸지는 실제로 돌려봐야 안다.

### Aura Free는 애초에 후보가 아니었다

내 그래프는 **노드 58.7만 / 관계 141.6만**. Aura Free 한도는
문서마다 다르게 적혀 있는데(FAQ 20만/40만, 제품 페이지 5만/17.5만)
**어느 쪽이든 3~8배 초과**다. 즉 "Aura Free vs EC2"가 아니라
"Aura 유료(월 $65~130) vs EC2(월 $19)"였다.

### Lambda는 15분이면 죽는다

적재를 Lambda로 할 수 있냐고 물었는데 안 된다.
5만 건 적재는 API를 250번 왕복하는 작업이라 15분을 넘는다.

**Lambda는 짧게 끝나는 이벤트 처리용, 적재는 오래 도는 배치.** 안 맞는다.
(6주차 에이전트는 질문 하나에 몇 초라 얘기가 다르다.)

### `latest` 태그는 재현 가능하지 않다

내 이미지 태그가 `neo4j`(= latest)다. 7/16자 이미지고 버전은 2026.06.0.
EC2에서 `docker pull neo4j` 하면 **오늘 시점의 latest**를 받는다. 다를 수 있다.

```bash
docker pull neo4j:2026.06.0   # 이렇게 박아야 한다
```

**볼륨 복사가 탈락한 이유가 이거다.** 파일을 날것으로 옮기는 방식이라
버전이 다르면 안 열릴 수 있다. dump는 Neo4j가 업그레이드 경로를 지원해서 안전마진이 크다.

> 버전을 확인하지 않았으면 볼륨 복사를 골랐을 것이다. **측정이 결정을 바꿨다.**

### SSM은 인스턴스 역할이 먼저 있어야 한다

역할이 두 개 필요하다는 걸 몰랐다.

- **인스턴스 역할** — EC2가 SSM에 "나 여기 있음" 등록
- **사용자 권한** — 내가 `aws ssm start-session` 호출

**EC2가 먼저 손을 들어야 내가 접속할 수 있다.**
인스턴스 역할이 없으면 SSM 콘솔에 인스턴스가 아예 안 보인다고 한다.

### SSM을 고르면 파일 전송 경로가 바뀐다

SSH가 없으니 `scp`를 못 쓴다. 그래서 S3를 경유한다.

```
맥북 ──aws s3 cp──→ S3 ──aws s3 cp──→ EC2
```

그래서 IAM 역할에 S3 읽기가 필요해졌다. **접속 방식 선택이 전송 방식과 IAM까지 끌고 왔다.**

## IAM 후보 셋에서 B를 고른 이유

Claude가 세 개를 줬다.

- **A**: `AmazonSSMManagedInstanceCore` 하나만
- **B**: A + S3 읽기 (버킷 하나로 한정)
- **C**: B + Bedrock 호출 권한 미리 추가

**B를 골랐다. 지금 필요한 만큼만.**

C는 4주차에 쓸 Bedrock 권한을 미리 넣는 안인데, 그러면 **한 달 넘게
안 쓰는 권한이 붙어 있게 된다.** IAM 역할은 나중에 정책을 언제든 추가할 수 있다.
A는 전송 경로를 따로 만들어야 해서 지금 할 일이 하나 더 는다.

이게 **최소권한(least privilege)** 이라는 걸 나중에 들었다.

  전제를 되묻는 것**이라는 얘기 (학습 목표 3에 정확히 걸린다)

- **"자격증은 큰 문제를 가르친다"** — SAA에서 배운 DMS·Snowball은 214MB에 안 맞는다.
  배운 도구를 찾는 게 아니라 문제 크기에 맞는 도구를 고르는 것.
  **자격증과 실무 사이의 간극을 규모로 설명**하는 글

- **"컨테이너를 옮긴다는 말은 성립하지 않는다"** — 이미지에는 내 데이터가 없다.
  프로그램과 데이터가 분리돼 있다는 걸 몰라서 "도커를 통째로 옮기나"라고 물었다.
  도커 볼륨을 처음 이해한 순간

- **"latest 태그는 재현 가능하지 않다"** — 버전을 확인했더니 볼륨 복사가 탈락했다.
  **측정이 결정을 바꾼 사례.** 8/13의 "측정은 행동이 갈릴 때만 의미가 있다"와
  짝이 되는 글 — 이번엔 실제로 갈렸다

- **"임베딩은 DB를 바꾸는 게 아니라 컬럼 하나 붙이는 것"** — 나는 그래프가 사라지고
  숫자만 남는 줄 알았다. "벡터DB"라는 말 때문에 옮기는 그림이 그려졌던 것 같다.
  **RAG 입문자가 처음 걸리는 지점**으로 쓸 만함

- **"Neo4j는 메모리를 두 번 잡는다"** — JVM 힙 + 페이지 캐시(off-heap).
  Spring 앱과 달리 DB는 자기 데이터를 자기가 들고 있어야 해서.
  힙이 모자라면 죽고 페이지 캐시가 모자라면 느려진다는 **결과의 비대칭**이 포인트

- **"모른다고 말한 게 제일 빨랐다"** — SSH를 안 써봤다고 말하기까지
  "이해 안 됨"을 세 번 반복했다. 배경 지식이 없는 걸 인정하는 순간
  설명이 그 층부터 다시 시작됐다
