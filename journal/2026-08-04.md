## 잘못 알고 있었던 것

### 1. "arXiv 응답에 author 정보만 있는 것 같다"

응답을 처음 보고 이렇게 읽었는데 틀렸다. 제목·초록·발행일·카테고리는 다 있었다.
**진짜 문제는 없는 쪽이었다.**

- 인용 관계가 통째로 없음 → 논문→논문 엣지를 만들 수 없음
- 저자가 이름 문자열뿐 → `Wei Zhao`가 수십 명인데 한 노드로 합쳐짐

두 번째가 더 무섭다는 걸 나중에 알았다. 인용이 없으면 그냥 못 만드는 건데,
저자 ID가 없으면 **틀린 답을 내는 그래프**가 만들어진다. 없는 것보다 나쁘다.

교훈: API 응답을 볼 때 "뭐가 있나"보다 **"내가 만들 관계에 필요한 게 뭐가 없나"**를 봐야 한다.

### 2. Neo4j를 "그래프DB 프레임워크"라고 불렀다

DBMS다. MySQL, PostgreSQL과 같은 급. 서버 띄우고 쿼리 언어(Cypher)로 접근하고 디스크에 남는다.

### 3. "벡터DB냐 그래프DB냐"가 애초에 틀린 질문이었다

오늘 제일 크게 바뀐 생각.

처음 던진 질문은 **"그래프DB 단독으로 '~~한 내용의 논문의 저자'를 어떻게 찾나?"**였다.
답은 "못 찾는다"였다. Cypher의 `CONTAINS`는 글자 맞추기라
`adversarial training`으로 검색하면 `adversarial robustness`라고 쓴 논문을 놓친다.

그래서 벡터가 필요한데 — **경쟁 관계가 아니라 역할이 다르다.**

```
1단계 (벡터)   질문 임베딩 → 초록 유사도 → 논문 20개    "어디서 시작할지"
2단계 (그래프) 그 20개에서 저자·인용 관계로 확장         "거기서 뭘 끌어올지"
```

그리고 **Neo4j 5.11+에는 벡터 인덱스가 내장돼 있다.** 임베딩은 별도 저장소가 아니라
노드 프로퍼티 하나고, 벡터 검색과 관계 탐색이 한 쿼리 안에서 끝난다.

```cypher
CALL db.index.vector.queryNodes('paper_abstract', 20, $questionVector)
YIELD node AS p
MATCH (p)-[:AUTHORED_BY]->(a:Author)
RETURN DISTINCT a.name
```

이걸 알고 나니 비교 대상 자체가 다시 정의됐다.
"벡터DB 제품 vs 그래프DB 제품"이 아니라:

```
벡터 RAG:   초록 top-k          → LLM
그래프 RAG: 초록 top-k → 확장   → LLM
                        ↑ 차이는 이 한 단계뿐
```

### 4. "학습 목적이면 벡터DB를 따로 쓰는 게 맞지 않나?"

Pinecone/Qdrant를 따로 붙이면 제품을 두 개 써보니 학습에 낫다고 생각했다. 아니었다.

- 제품 두 개를 세팅하는 건 학습이 아니라 세팅 경험이다. API는 반년이면 바뀐다
- 내 학습 목표 5번은 "차이를 알고 **선택**"인데, 그 차이는 제품이 아니라 **검색 방식**에 있다
- DB가 하나면 인프라 변수가 빠져서 5주차 비교가 오히려 깨끗해진다
- 무엇보다 버퍼 없는 8주 계획에서 며칠이 빠지면 그건 7주차 멀티에이전트에서 나온다

실무에서 A/B가 갈리는 기준도 "실무니까 A"가 아니라 **규모**였다.
벡터가 수천만~억 건이면 전용 제품이 이기고, 수만 건이면 Neo4j 내장으로 충분하다.

## 알게 된 것

### OpenAlex는 2026년 2월부터 유료화됐다 (단, 우리 규모는 무료)

| 엔드포인트 | 호출당 |
|---|---|
| 단일 조회 (ID/DOI) | $0 |
| list + filter | $0.0001 |
| search | $0.001 (filter의 10배) |
| PDF 다운로드 | $0.01 |

무료 한도 $1/day (키 없으면 $0.10). 논문 5만 건 적재 = 500 calls = **$0.05**.

데이터셋 자체는 여전히 무료 — 과금 대상은 API 서비스다.

**여기서 설계 제약 하나가 나왔다:** `search=`를 쓰지 말 것. 어차피 의미 검색은
Neo4j 벡터 인덱스가 하므로 OpenAlex search를 쓸 이유가 없다.

### 인용·저자는 추가 호출이 필요 없다

`referenced_works`와 `authorships`가 논문 응답에 인라인으로 들어 있다.
**논문 목록만 페이징하면 그래프 전체가 딸려온다.** 적재 파이프라인이 예상보다 단순해졌다.

### 초록이 뒤집혀 있다

OpenAlex는 `abstract_inverted_index`로 준다. `{"Deeper": [0], "neural": [1], ...}` 형태.
저작권 때문에 원문 그대로는 안 주는데, **위치를 다 주므로 복원에 손실이 거의 없다.**
20줄이면 되돌릴 수 있다. 처음엔 이것 때문에 arXiv를 병행할까 고민했는데 근거가 안 됐다.
